# The Ever-Unfolding Saga

## Roadmap

The roadmap tracks current and upcoming development. Detailed completed milestone history is kept in [`docs/roadmap-history.md`](docs/roadmap-history.md). The intended product direction is recorded in [`docs/design-principles.md`](docs/design-principles.md); this roadmap distinguishes those long-term goals from what is currently implemented and validated.

## Current state

**v0.52.3 — Options save metadata and UI polish; shared interface preferences, fullscreen presentation, reusable Options row layout, and storage/mod-management redesign implemented.** Each installation now has one application-managed data root: the OS local application-data directory on desktop and private app files on Android. Game-root selection, Android SAF tree permissions, shared-folder mirroring, and multiple-root discovery have been removed. The Options screen provides explicit save import/export and ZIP mod installation/management. Mods may be content-bearing, asset-only, or both; custom assets are mod-owned and override bundled defaults by deterministic mod priority. Cross-mod event references are validated after all enabled mod definitions are merged. Save imports use exclusive file creation, and save metadata records active mod IDs, names, and versions, with load warnings for missing, disabled, or mismatched dependencies. Android refreshes its bundled asset cache from the packaged files while keeping installed mod packages user-managed. Mod settings take effect on the next process initialization; the running session uses a startup snapshot. No migration from previous selectable roots is included. Desktop now starts fullscreen instead of offering windowed-resolution presets; Android retains immersive landscape presentation. Both platforms share persistent, independently configurable UI scaling and font sizing in the Interface Options tab. The touchscreen developer-console shortcut is documented: long-press the gameplay pause button for 650 ms without dragging. Options now uses one reusable landscape row pattern across Saves, Mods, and Interface: option names stay left, with horizontal controls and current values on the right. Save export buttons sit beside their save entries; mod enable/disable, delete, and priority controls sit beside each mod; Interface rows show decrement, current value, and increment controls. Each tab's entries scroll independently inside the fixed screen frame, while Save Import, Mod Install, Interface Reset, and Back actions remain in a persistent bottom footer. Save rows in Options and Load show character, world/progression, save-format, and saved mod-dependency metadata, falling back to the filename when metadata is unavailable. Options keeps its explanatory copy limited to the import no-overwrite guarantee and current status notices. Implementation details for storage and mods are tracked in [#385](https://github.com/Golden-Bastion/ashen_chronicle/issues/385).

**v0.52.x — location banner prototype complete.** Ashen Gate uses a full-width pixel-art PNG banner with nearest-neighbor sampling; other locations and banner-load failures retain the ASCII fallback.

## Active milestone

**v0.52.x — Procedural spatial exploration prototype** ([tracking issue #353](https://github.com/Golden-Bastion/ashen_chronicle/issues/353))

The first implementation slice is tracked in [#354 — spatial state and deterministic local-map generation](https://github.com/Golden-Bastion/ashen_chronicle/issues/354), [#355 — continuous movement and discovery](https://github.com/Golden-Bastion/ashen_chronicle/issues/355), and [#356 — exploration persistence and inheritance](https://github.com/Golden-Bastion/ashen_chronicle/issues/356).

The renderer-neutral map model and deterministic generator are in place, alongside the Bevy exploration view for dangerous locations, continuous keyboard/touch movement with blocked-terrain collision, angled tile projection, and depth ordering. Flat floor, ash, and rubble tiles now use a background layer so they cannot cover the player. Player depth follows continuous ground position, and wall tops/faces use their ground-contact lines for occlusion ordering. The view includes a contextual point-of-interest interaction recorded in world history. World-persistent local maps live in the saved world state; exact active exploration position/session live with the character. The viewport-scaled camera dead zone and bounds for wall geometry are implemented. Physical edge passages are derived from connected world-location IDs and require proximity/clear approach; until all connected destinations have spatial maps, using a passage returns to normal gameplay just like `Leave`. First-pass pixel-art tiles now distinguish wood flooring, ash, rubble, and wall tops, with a character sprite and passage marker. Spatial UI icons use named PNGs from protected bundled base assets and the shared mod-aware runtime loader. Mods can replace a base asset by providing the same relative path under their own `assets/` directory; the highest-priority enabled mod wins, with stable manifest ID as the deterministic tie-break. Explicit references use `mod:<manifest-id>/<relative-path>`. Missing icons are logged and omitted rather than rendered as Unicode or white-glyph placeholders. Basic deterministic pillar/table prop collision and occlusion are now part of the prototype. Old Shrine content selects a first authored chamber template with intersecting walls, a doorway, a pillar, and a table ([tracking issue #381](https://github.com/Golden-Bastion/ashen_chronicle/issues/381)); its geometry is generated only for new local maps and then persists with the map. Arbitrary room graphs, additional authored templates, full room/door topology, and room-aware camera transitions remain future work. Desktop/Android end-to-end validation remains outstanding and is intentionally left to the repository owner. Spatial controls expose eight-way directional input for diagonal movement, UI scroll panels consume desktop mouse-wheel input as well as touch drags, button actions activate on completed clicks, and touch-scroll gestures suppress activation of the button they began on. Spatial exploration uses an Android-only analog virtual joystick with a dead zone and pressure-scaled movement; desktop movement is keyboard-driven with no on-screen directional pad. Spatial exploration now also has a compact persistent vitals panel showing character identity/level, current/max health, and active conditions, using the shared health-gauge primitive. A targeted wall-top depth-tie correction ensures the player wins equal-depth ordering; device/manual playtesting remains pending, and full room/prop occlusion is still future work.

Keep the existing world model, quests, time, narrative, and location-level actions authoritative. Spatial exploration supplements rather than replaces them. Real-time spatial combat and audio remain outside this milestone.

Related design issues: [#228 — long-term hybrid exploration](https://github.com/Golden-Bastion/ashen_chronicle/issues/228), [#229 — incremental pixel-art direction](https://github.com/Golden-Bastion/ashen_chronicle/issues/229), and [#252 — spatial combat design](https://github.com/Golden-Bastion/ashen_chronicle/issues/252).

## Longer-term direction

Continue modularizing the codebase by responsibility rather than by file size alone. Keep runtime state, content loading, gameplay actions, presentation, persistence, and event processing independently understandable and testable.

The product direction is a character-focused, graphics-first spatial RPG backed by a persistent simulation. Spatial exploration is being delivered incrementally; real-time spatial action combat and audio integration remain future work, not current milestone claims. Keep world systems character-centred rather than turning them into remote grand-strategy management. Desktop and mobile support, hybrid input, scalable visual/simulation quality, offline single-player, player-controlled updates, and robust save/mod compatibility remain guiding constraints. See the [design principles](docs/design-principles.md).

Major gameplay work should remain data-driven where practical, preserve backward compatibility, and include focused tests for behavior affected by the change.
